## 二、日常常用命令速查

在 Foundry 项目目录（含 `foundry.toml` 的目录，例如 `Task1/`）下运行：

```bash
forge build              # 编译合约
forge test               # 运行所有测试
forge test -vv           # 显示日志（-vvv 显示 trace，-vvvv 最详细）
forge test --gas-report  # 运行测试并输出 gas 消耗报告
forge test --match-test testDepositUSDT   # 只跑某个测试函数
forge fmt                # 格式化 Solidity 代码
forge clean              # 清除编译缓存（out/、cache/）
```

依赖管理：

```bash
forge install foundry-rs/forge-std   # 安装依赖（拉到 lib/ 下，需要项目是 git 仓库）
forge install OpenZeppelin/openzeppelin-contracts   # 例：安装 OZ 合约库
forge update             # 更新所有依赖
forge remove forge-std   # 移除依赖
```

本地链与交互：

```bash
anvil                    # 启动本地测试链（默认 http://127.0.0.1:8545，带 10 个测试账户）
cast balance <地址>      # 查 ETH 余额
cast call <合约> "balanceOf(address)" <地址>   # 只读调用合约
```

版本升级：

```bash
foundryup                # 升级 Foundry 到最新版（已在 PATH 中）
```

## 三、新建一个 Foundry 项目

```bash
forge init my-project    # 新建并初始化（自动建 src/ test/ script/ 和 git）
cd my-project
forge test               # 自带一个示例测试，确认环境正常
```

如果是在已有目录里初始化（目录非空）：

```bash
forge init --no-git .    # 当前目录初始化，不新建 git
```

## 四、VS Code 推荐插件清单

打开 VS Code → 扩展市场（Ctrl+Shift+X）搜索安装：

| 插件 | 标识符 | 作用 | 必要性 |
|---|---|---|---|
| **Solidity** (Nomic Foundation) | `NomicFoundation.hardhat-solidity` | 官方推荐，语法高亮、跳转、错误提示，对 Foundry 项目支持好 | 强烈推荐 |
| Solidity (Juan Blanco) | `JuanBlanco.solidity` | 老牌 Solidity 插件，功能类似，二选一即可 | 可选 |
| Even Better TOML | `tamasfe.even-better-toml` | 高亮 / 校验 `foundry.toml` | 推荐 |
| Error Lens | `usernamehw.errorlens` | 把报错直接显示在代码行内 | 可选，提效 |
| GitLens | `eamodio.gitlens` | Git 增强 | 可选 |

> 注意：**Nomic Foundation 的 Solidity 插件**和 **Juan Blanco 的 Solidity 插件**不要同时启用，会冲突。推荐只用 Nomic Foundation 那个。

命令行装法（如果想用命令）：

```bash
code --install-extension NomicFoundation.hardhat-solidity
code --install-extension tamasfe.even-better-toml
```

### 让插件正确识别 Foundry 项目

Nomic Foundation 插件默认能读 `foundry.toml`。如果出现 import 找不到（红线但能编译），在项目根目录建一个 `remappings.txt`：

```bash
forge remappings > remappings.txt
```

里面通常是类似 `forge-std/=lib/forge-std/src/` 的映射，VS Code 插件会读它来解析 import。

## 六、常见问题

**Q：重开终端后 `forge` 还是找不到？**
A：确认是「新开窗口」而非旧窗口。VS Code 里需重启 VS Code（或重开集成终端面板）才会重新读环境变量。

**Q：`forge install` 报错？**
A：该命令依赖 git submodule，项目目录（或其父目录）必须是 git 仓库。本项目父目录 `f:\Blockspace` 已是 git 仓库，正常可用。

**Q：编译时第一次很慢？**
A：forge 在首次编译时会下载对应版本的 solc 编译器（本项目是 0.8.20），下载后会缓存，之后就快了。

**Q：想换 solc 版本？**
A：改 `foundry.toml` 里的 `solc = "0.8.xx"`，forge 会自动下载对应版本。
