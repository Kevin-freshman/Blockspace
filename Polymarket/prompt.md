# Polymarket 聪明钱分析工具 — Prompt 集

> 使用方法：按项目阶段选择对应的 Prompt，复制给 AI 使用。先用「需求拆分 Prompt」启动项目，确认模块设计后再进入「代码实现 Prompt」。

---

## 1. 需求拆分 Prompt（项目启动时用）

```
【背景】
我要做一个 Polymarket 聪明钱分析工具（MVP 优先）。
Polymarket 是一个预测市场：每个赌局（market）发行 YES/NO 两种 token，
用户通过中心化撮合（链下 orderbook）+ 链上结算（Polygon）进行交易。
由于赌局涉及现实事件，存在内幕交易和套利空间，
我想通过分析高收益地址的行为模式来发掘市场热点和聪明钱模式。

【目标（MVP 范围）】
1. 收益分析：找出 Polymarket 上收益最高的前 100 / 前 1000 个地址，
   记录并持续追踪他们的全部交易。
2. 模式聚类：把这些地址的交易行为整理成简单文本摘要，
   交给大模型做聚类和模式识别，例如：
   - 套利型（跨市场 / YES+NO 价差套利）
   - 疑似内幕型（长期高胜率、事件揭晓前精准建仓的"一直赢的赌狗"）
   - 趋势型 / 做市型等其他模式
3. 热点挖掘：从聪明钱的近期动向中发现值得关注的市场（挖 funding / alpha），
   crypto 类赌局单独作为一个模块（可套利场景）。

【数据来源】
- Polymarket 官方文档和公开 API（CLOB API、Gamma API、Data API）
- Polygon 链上数据（结算、转账、USDC 流向）
- 先读文档，确认每个数据字段从哪里取

【你的任务 —— 只做设计，不要写完整代码】
1. 拆分模块（数据采集 / 收益计算 / 行为摘要 / LLM 聚类 / 报告输出）
2. 为每个模块定义清晰的 data schema（字段名、类型、含义、来源）
3. 列出模块之间的接口（函数签名 + 输入输出）
4. 列出每个模块的测试要点
5. 指出 MVP 阶段可以砍掉的部分和明确的先后顺序

【禁止事项】
- 不要直接输出完整项目代码
- 不要假设不存在的 API 字段，不确定的字段标注"需查文档确认"
```

## 2. 代码实现 Prompt（模块设计确认后，逐模块使用）

```
【背景】
Polymarket 聪明钱分析工具，模块设计和 schema 已确认（见下方）。
现在实现【<填模块名，如：数据采集模块>】。

【Schema】
<粘贴该模块确认后的 data schema>

【技术栈与约束】
- Python；链上数据用 web3.py + eth_getLogs，链下数据用 Polymarket 公开 API
- 大区块范围 / 大时间范围必须分块查询，不能一次拉全量
- 必须处理 API rate limit（退避重试），网络错误要有重试机制
- 所有配置（RPC 地址、API key、地址列表、区块范围）从 config.yaml 读取，
  禁止硬编码
- 每条链上记录必须保留 tx_hash / block_number / timestamp / log_index，
  保证可复现、可去重
- 注意 token decimals（USDC 是 6 位），金额计算不能出错
- 数据落地为本地文件（csv/parquet/sqlite 任选其一，说明理由）

【输出要求】
- 该模块的完整代码 + 一个最小可运行示例
- 简要说明关键设计决策（分块大小、重试策略、去重方式）

【禁止事项】
- 不要引入本模块不需要的依赖
- 不要顺手修改其他模块
```

## 4. Code Review Prompt（模块完成后用）

```
【背景】
请 review 以下 Polymarket 数据分析代码。

【代码】
<粘贴代码>

【重点检查项】
1. 日志完整性：分块查询是否会漏日志或重复计算（边界区块处理）
2. decimals 是否正确（USDC 6 位；YES/NO token 精度需确认）
3. 是否有 rate limit 处理和网络重试机制
4. 每条记录是否保留 tx_hash / block_number / timestamp / log_index
5. 结果是否可复现（相同 config 跑两次结果一致，去重逻辑正确）
6. 配置是否全部来自 config.yaml，有无硬编码

【输出要求】
按"问题 - 严重程度 - 修改建议"逐条列出，没有问题的检查项也要说明"已确认"。
```

## 5. 报告生成 Prompt（分析产出时用）

```
【背景】
基于以下 Polymarket 聪明钱分析数据，生成分析报告。

【数据】
<粘贴分析结果：地址收益排名、聚类结果、交易摘要等>

【报告要求】
1. 每个结论必须标注 evidence level：
   - [on-chain fact]（链上事实，可直接验证）
   - [reasonable inference]（合理推断，说明推断依据）
   - [unverified hypothesis]（未验证假设，明确标注）
2. 对疑似内幕地址，只描述行为模式（胜率、建仓时点与事件揭晓的时间关系），
   不下定性结论
3. 报告结构：摘要 → 收益排名 → 模式聚类 → 热点市场 → 风险与局限

【禁止事项】
- 禁止写任何投资建议
- 禁止把"资金转入 CEX"描述为"已经卖出"
- 禁止在没有链上证据的地方使用肯定语气
```
