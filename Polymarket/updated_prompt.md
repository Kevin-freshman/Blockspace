# Polymarket 聪明钱分析工具 — Prompt 集（v2）

> 使用方法：按项目阶段选择对应的 Prompt，复制给 AI 使用。
>
> **核心工作原则（来自实践经验 + "Finding Your Unknowns" 方法论）：**
> 1. **地图不等于疆域。** Prompt 是地图，真实数据和代码是疆域，两者的差距是"未知"。项目各阶段都要主动让 AI 帮你发现未知，而不是假装计划已经完备。
> 2. **AI 写代码可以、做数据总结还行，但多数 finding 来自你自己的分析。** 所以 prompt 的目标不是让 AI 直接给结论，而是让 AI 产出便于人工审阅的中间产物（表格、摘要、证据链），你自己看、自己发现模式。
> 3. **不要把 prompt 写得太死，也不要太松。** 写太死，AI 会在该转向时死守指令；写太松，AI 会用不适合任务的默认做法填空。对不确定的部分，明确告诉 AI "这里我不确定，你可以提出更好的做法"。

## 0. 盲区扫描 Prompt（项目启动前，先用这个）

```
【背景】
我要做一个 Polymarket 聪明钱分析工具（详细目标见后续需求）。
我熟悉的部分：Python、基本的链上数据概念（event log、ERC20）。
我不熟悉的部分：Polymarket 的撮合与结算机制细节、CLOB/Gamma/Data API 的
具体能力边界、预测市场的收益计算方式。

【你的任务 —— 帮我发现"未知的未知"（blindspot pass）】
1. 列出做这类分析工具时，像我这样背景的人最容易踩的坑和盲区
   （数据层面、机制层面、分析方法层面各列几条）
2. 列出我应该在动手前搞清楚、但很可能还没想到要问的问题
3. 之后请采访我：一次只问一个问题，优先问答案会改变整体架构的问题

【禁止事项】
- 不要开始写代码或设计模块
```

## 1. 需求拆分 Prompt（盲区扫描后，项目启动时用）

```
【背景】
我要做一个 Polymarket 聪明钱分析工具（MVP 优先）。
Polymarket 是一个预测市场：每个赌局（market）发行 YES/NO 两种 token，
用户通过中心化撮合（链下 orderbook）+ 链上结算（Polygon）进行交易。
由于赌局涉及现实事件，存在内幕交易和套利空间，
我想通过分析高收益地址的行为模式来发掘市场热点和聪明钱模式。

【目标（MVP 范围）】
1. 收益分析：找出 Polymarket 上收益最高的前 100 / 前 1000 个地址，
   记录并持续追踪他们的全部交易。
2. 行为摘要与画像表：把每个地址的交易行为整理成结构化摘要，
   由大模型生成一张「账户画像表」供我人工审阅（详见分析 Prompt）。
   注意：模式分类是开放式的，不预设固定类别；
   最终的模式发现和判断由我自己完成，AI 负责准备好素材。
3. 热点挖掘：从聪明钱的近期动向中发现值得关注的市场（挖 funding / alpha），
   crypto 类赌局单独作为一个模块（可套利场景）。

【数据来源】
- Polymarket 官方文档和公开 API（CLOB API、Gamma API、Data API）
- Polygon 链上数据（结算、转账、USDC 流向）
- 先读文档，确认每个数据字段从哪里取

【你的任务 —— 只做设计，不要写完整代码】
1. 拆分模块（数据采集 / 收益计算 / 行为摘要 / 画像表生成 / 报告输出）
2. 为每个模块定义清晰的 data schema（字段名、类型、含义、来源）
3. 列出模块之间的接口（函数签名 + 输入输出）
4. 列出每个模块的测试要点
5. 指出 MVP 阶段可以砍掉的部分和明确的先后顺序

【输出顺序要求】
把我最可能想改的决策放在最前面：data schema、画像表的字段设计、
模块边界；机械性的实现细节放最后。

【禁止事项】
- 不要直接输出完整项目代码
- 不要假设不存在的 API 字段，不确定的字段标注"需查文档确认"
- 设计中如果发现我的需求本身有问题（比如"前 100 收益地址"的
  定义有歧义：已实现收益还是浮盈？什么时间窗口？），
  直接指出来并给出选项，不要替我默默选一个
```

## 2. 代码实现 Prompt（模块设计确认后，逐模块使用）

```
【背景】
Polymarket 聪明钱分析工具，模块设计和 schema 已确认（见下方）。
现在实现【<填模块名，如：数据采集模块>】。

【Schema】
<粘贴该模块确认后的 data schema>

【技术栈与约束】
- Python；链上数据用 web3.py + eth_getLogs，链下数据用 Polymarket 公开 API
- 大区块范围 / 大时间范围必须分块查询，不能一次拉全量
- 必须处理 API rate limit（退避重试），网络错误要有重试机制
- 所有配置（RPC 地址、API key、地址列表、区块范围）从 config.yaml 读取，
  禁止硬编码
- 每条链上记录必须保留 tx_hash / block_number / timestamp / log_index，
  保证可复现、可去重
- 注意 token decimals（USDC 是 6 位），金额计算不能出错
- 数据落地为本地文件（csv/parquet/sqlite 任选其一，说明理由）

【实现笔记要求】
维护一份 implementation-notes.md。实现过程中如果遇到迫使你偏离
设计的情况（API 字段和文档不符、数据缺失、边缘情况等），
选保守方案，记录在 "Deviations" 一节，然后继续，不要停下来等我。

【输出要求】
- 该模块的完整代码 + 一个最小可运行示例
- 简要说明关键设计决策（分块大小、重试策略、去重方式）

【禁止事项】
- 不要引入本模块不需要的依赖
- 不要顺手修改其他模块
```

## 3. 账户画像与分析 Prompt（数据到位后，核心分析环节用）

```
【背景】
我已采集到 Polymarket 高收益地址的交易数据（见下方/附件）。
你的角色是分析助手：负责整理素材、提出假设；
最终的模式发现和判断由我自己完成。

【数据】
<粘贴或引用：地址列表、每个地址的交易记录/持仓/盈亏摘要>

【你的任务】
1. 为每个地址生成一张「账户画像表」，字段包括：
   - 地址
   - 行为描述（用 2-3 句自然语言概括这个地址在做什么）
   - 关键统计：总盈亏、胜率、交易次数、平均持仓时间、
     主要参与的市场类别（政治/体育/crypto/...）
   - 值得注意的细节（如：总在事件揭晓前 X 小时建仓、
     只做某一类市场、YES/NO 同时持有、资金来源特征等）
   - 你的初步假设（这个地址可能在用什么策略）+ 置信度和依据
2. 在表之后，自由地做开放式归纳：你观察到哪些反复出现的模式？
   哪些地址看起来相似？有没有你觉得奇怪、值得我深挖的地方？
   不要局限于任何预设分类。
   （套利、疑似内幕、做市等只是可能的例子，不是选项清单；
   如果数据呈现出这些类别之外的模式，直接说出来。）
3. 给我列出 5-10 个值得人工深挖的地址，并说明为什么。

【输出要求】
- 画像表用 markdown 表格（或 csv），方便我逐行审阅
- 每个假设标注依据是什么数据，不确定就说不确定
- 区分"数据里能看到的"和"你推测的"

【禁止事项】
- 不要直接给出"这就是内幕交易"之类的定性结论
- 不要为了凑分类而强行归类，宁可标注"模式不明"
```

## 5. Code Review Prompt（模块完成后用）

```
【背景】
请 review 以下 Polymarket 数据分析代码。

【代码】
<粘贴代码>

【重点检查项】
1. 日志完整性：分块查询是否会漏日志或重复计算（边界区块处理）
2. decimals 是否正确（USDC 6 位；YES/NO token 精度需确认）
3. 是否有 rate limit 处理和网络重试机制
4. 每条记录是否保留 tx_hash / block_number / timestamp / log_index
5. 结果是否可复现（相同 config 跑两次结果一致，去重逻辑正确）
6. 配置是否全部来自 config.yaml，有无硬编码

【输出要求】
按"问题 - 严重程度 - 修改建议"逐条列出，没有问题的检查项也要说明"已确认"。
```

## 6. 报告生成 Prompt（分析产出时用）

```
【背景】
基于以下 Polymarket 聪明钱分析数据和我人工确认过的发现，生成分析报告。

【数据】
<粘贴：地址收益排名、账户画像表、我人工审阅后确认的模式和发现>

【报告要求】
1. 报告只呈现我确认过的发现；AI 生成的未经确认的假设
   放在附录"待验证假设"中，明确标注
2. 每个结论必须标注 evidence level：
   - [on-chain fact]（链上事实，可直接验证）
   - [reasonable inference]（合理推断，说明推断依据）
   - [unverified hypothesis]（未验证假设，明确标注）
3. 对疑似内幕地址，只描述行为模式（胜率、建仓时点与事件揭晓的时间关系），
   不下定性结论
4. 报告结构：摘要 → 收益排名 → 账户画像与模式发现 → 热点市场 → 风险与局限

【禁止事项】
- 禁止写任何投资建议
- 禁止把"资金转入 CEX"描述为"已经卖出"
- 禁止在没有链上证据的地方使用肯定语气
```

## 7. 理解确认 Prompt（每个大模块合并前用，可选）

```

1. 给我写一份说明：这次改动做了什么、为什么这么做、
   有哪些关键决策和已知局限（结合 implementation-notes.md 中的 Deviations）
2. 在最后出 5 道关于这次改动的测验题（涉及数据流、边界情况、配置项），
   我全部答对才算我真正理解了这次改动
```
