# Polymarket Crypto Top 5 项目边界与决策

本文档记录当前已经确定、后续实施不得静默改变的项目边界和设计决策。尚未确认的接口、地址、阈值或来源不属于既定事实，必须保持 `[待核验]`。

## 1. 数据与目录边界

- 项目唯一工作根目录是 `crypto_top5_analysis`。
- 不读取、连接、复制、导入或参考任何既有 Polymarket SQLite 数据库。
- 不上传或使用用户 Windows 设备上的大型旧数据库。
- 不使用服务器上的任何旧轻量数据库。
- 新项目只创建独立数据库 `data/db/top5.sqlite3`。
- 不修改相邻 tracker 项目及其 HTML。
- 所有未来写入只能发生在 `crypto_top5_analysis` 内。
- 只有 `public/` 可以作为公网 document root。
- `data/`、`logs/`、`reports/`、数据库、raw 响应和 Parquet 永远不得公开。
- 禁止通过符号链接、路径穿越或动态后端间接公开私有目录。

- 上述数据是用户提供的不可覆盖种子快照。
- 列表序号已经确认为种子排名 1–5。
- 原始快照时间未知，`snapshot_as_of_utc` 保存为 NULL；另存信息录入时间，不伪造快照时点。
- 当前官方排行榜数据必须另存为观察快照，不得覆盖种子数据。
- 用户名、完整地址和地址前后缀是严格身份门槛。
- 排名、PnL 和成交量必须逐项核对并留痕；因排行榜变化造成的数值差异不单独阻断，也不得静默替换种子。
- 第一阶段必须得到恰好五个互不相同的完整 `proxyWallet`。
- 缩写地址不得作为任何账户采集参数。
- 无法得到恰好五个唯一完整地址时必须停止并询问用户。

## 3. 白名单和采集边界

- `targets.yaml` 是所有账户型 HTTP 请求的唯一地址白名单。
- `targets.yaml` 只在五个身份全部验证成功后生成和锁定。
- 锁定前只允许不带用户地址参数的官方排行榜身份解析请求。
- HTTP 客户端必须在请求序列化前拒绝任何不在白名单内的 `user` 或 `address` 参数。
- 研究采集五个目标账户的全部可获得 Polymarket 历史，Crypto 是报告重点，非 Crypto 是对照基线。
- Trades 固定使用 `takerOnly=false`、`start=1`；具体接口语义仍为 `[待核验]`。
- 市场数据只采集五人实际交易过的市场和 outcome token。
- 可以保存目标交易直接出现的对手方、资金来源和路由地址。
- 禁止递归采集任何外部地址的完整历史。
- 五目标之间的直接关系及共同直接资金来源可以分析，但证据范围必须明确限定为已观察到的目标交易边。

## 4. 来源与审计决策

每次请求必须保存：

- `source_request_id`
- 不含敏感参数的完整 URL
- `requested_at_utc`
- HTTP status
- 原始响应 SHA-256
- 响应记录数
- 分页窗口和页参数
- raw gzip 路径
- collector version
- Git commit

其他决定：

- Raw 数据保存为 `data/raw` 下不可覆盖的 gzip JSON。
- API key、RPC key 和其他秘密只从环境变量读取。
- 认证 header 不写入数据库或日志。
- 记录 URL 时将 `apikey` 的值替换为 `REDACTED`。
- 如响应体意外包含已知密钥，停止持久化并产生安全错误，不把含密钥内容落盘。
- 每个派生指标保存公式版本、输入快照哈希、计算时间和代码 commit。
- 每条链上证据必须有 PolygonScan 交易或地址链接。
- 请求成功不等于历史完整；完整性必须由覆盖窗口、终止条件、记录计数和响应哈希证明。

## 5. 存储与数值决策

- 数据库位置固定为 `data/db/top5.sqlite3`。
- 模型特征保存为 `data/derived` 下的 Parquet。
- 网页只读取 `public/data` 中经过字段白名单导出的汇总 JSON。
- SQLite 必须启用外键；所有用户级数据必须带非空 `target_id` 并引用五个 targets 之一。
- 数据库必须拒绝第六个 target，发布验收要求 target 数量恰好为五。
- 地址规范化为小写 42 字符地址，可另存 checksum 展示形式。
- 美元使用 `microusd` 或 Decimal，价格使用固定精度；审计指标不得依赖二进制浮点结果。
- UTC 是存储、特征和图表的统一时间标准；每个图表必须明确标出时区。

## 6. 分页与完整性决策

- 所有分页支持断点续传、幂等写入和自然键/规范哈希去重。
- offset 达到上限前按 UTC 时间窗口递归二分。
- 逻辑窗口默认采用半开区间；接口若只能使用包含边界，则使用最小重叠并去重。
- 最小时间粒度仍超限且没有稳定 cursor 或次级排序时，状态必须为 `blocked`，不得宣称完整。
- 覆盖状态固定为 `complete`、`partial` 或 `blocked`。
- 每个账户和数据集必须输出窗口树、缺口、重复、唯一数、首末时间、终止依据和响应哈希 Merkle root。

## 7. 链上数据决策

- 链固定为 Polygon，chain ID 137。
- 采集普通交易、internal transactions、ERC-20/ERC-1155 transfer、receipt、logs 和 block timestamp。
- Split、Merge、Redeem 和其他 Polymarket 合约交互只能根据官方确认的合约地址、ABI 和链上证据分类。
- explorer 负责目标地址账户历史，RPC 负责 receipts/logs/block timestamps、已确认合约过滤及交叉验证。
- 区块范围遇到提供商上限时递归二分。
- explorer 与 RPC 冲突时保留双方证据并标记，不静默择一。
- 合约注册表、ABI、供应商接口和最终性确认规则仍为 `[待核验]`。

## 8. 分析口径决策

- 独立 PnL 采用双口径：已实现 PnL，以及包含未平仓截止估值的总经济 PnL。
- 已实现 PnL 和持仓时间采用 FIFO lot 匹配。
- 无可靠截止价格的未平仓仓位不得按零估值，相关总 PnL 标为 unavailable 或 partial。
- 官方 PnL、种子 PnL 和独立重算 PnL分别保存。
- PnL 差异只比较同一截止点和可比范围。
- PnL/成交量必须明确说明不是 ROI。
- 百分比最大回撤只有在资金流完整、可重建资本基数时计算；否则只报告 USD 回撤。
- Maker/Taker 只接受明确字段或已验证撮合证据，不能根据 BUY/SELL 推断；证据不足为 unavailable。
- 三类固定特征表为 `account_day_features`、`account_market_features`、`trade_context_features`。

## 9. 异常信号和措辞边界

- 异常模块只输出“需要进一步核查”的信号。
- 禁止作出内幕交易、对敲、共同控制等确定性指控。
- 信号必须包含规则、阈值、交易证据、链上 URL、公开消息 URL或“不适用”原因、替代解释、数据局限和核查优先级。
- 数据或样本不足时必须使用 unavailable 或 low confidence。
- 公开消息范围已确定为“来源白名单 + 人工补充 URL”。
- 首批消息来源和异常阈值尚待用户批准。

## 10. HTML 和公开边界决策

- 报告采用纯静态站点，由 Python 离线生成。
- 页面范围至少包括一个总览页、五个账户详情页和完整 Glossary 页面。
- 浏览器不连接 SQLite、原始 API 或动态后端。
- 每个专有名词首次出现时提供支持悬停、键盘聚焦和手机点击的中文解释。
- 每张图必须展示问题、轴含义、单位、时区、公式、图例、样本量、覆盖期、来源、读图指导和局限。
- 禁止未解释坐标轴、未注明时区、只靠颜色区分买卖和容易误读的双 Y 轴。
- 所有表格列名提供解释、单位、排序和来源。
- 页面默认截断地址文字；证据链接可包含完整链上地址或交易哈希，此展示方式仍需实施前最终确认。
- 不使用外部 CDN、在线字体或运行时 API。

## 11. 已确认与待确认事项

已确认：

- 种子排名为 1–5。
- 种子快照时间未知并保存为 NULL。
- 身份严格核验，动态数值差异留痕但不覆盖。
- PnL 采用双口径。
- 公开消息使用白名单加人工补充。
- 网页使用纯静态方案。

实施前待确认：

1. 七类异常规则的具体默认阈值。
2. 首批公开消息来源白名单。
3. Polygon explorer/RPC 提供商及环境变量名；不得在对话中提供密钥值。
4. Polymarket 官方接口、分页上限、`start=1` 语义、Polygon 合约/ABI 和最终性规则。
5. 公开页面地址截断与完整链上链接的展示政策。
6. 五地址严格验证成功后自动锁定 `targets.yaml`，还是仍要求逐地址人工批准。
