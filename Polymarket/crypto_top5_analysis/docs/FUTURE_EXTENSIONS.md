# Future Extensions

以下项目均未在本轮完成。它们不阻塞基于现有证据的 MVP 报告，但实施前必须
另行确认数据源、隐私边界、公式与验收标准。

## 1. proxyWallet、EOA 与资金来源归因

- 研究价值：区分 Profile Address、实际签名账户与直接资金来源。
- 所需新增数据：官方账户架构文档、链上交易、钱包部署关系。
- 依赖：已确认合约地址、ABI、Polygon 数据源。
- 实现难点：代理钱包、托管、路由与账户抽象可能混淆控制关系。
- 风险或误判来源：把交互地址误认为实际控制人或最终受益人。
- Acceptance criteria：每个归因结论绑定官方架构证据和具体链上交易，未知项
  保持 unresolved。
- 建议优先级：高。

## 2. Polygon 链上资金流及跨链桥分析

- 研究价值：重建目标地址可观察的直接入出金与跨链路径。
- 所需新增数据：Polygon 交易、internal transaction、token transfer、receipt、
  logs、桥合约事件。
- 依赖：获批 explorer/RPC、最终性规则、桥合约注册表。
- 实现难点：链上重组、桥接消息配对、token decimals 与价格折算。
- 风险或误判来源：路由地址、归集地址或桥池不等于资金实际来源。
- Acceptance criteria：覆盖窗口无缺口，每条桥接关联有双链可验证证据。
- 建议优先级：中。

## 3. CEX 入金/出金识别

- 研究价值：标记与已知交易所服务地址的直接交互。
- 所需新增数据：有版本和出处的 CEX 地址标签、链上转账。
- 依赖：可靠标签供应商及许可审查。
- 实现难点：热钱包轮换、共享充值地址和中间路由。
- 风险或误判来源：标签过期或把共享基础设施当作账户关联。
- Acceptance criteria：标签带来源、有效期和置信度；报告只描述直接交互。
- 建议优先级：低。

## 4. Counterparty-level wash trading 检测

- 研究价值：识别需要进一步核查的短时双边反复成交模式。
- 所需新增数据：完整逐笔成交、可靠 maker/taker 或撮合对手方证据。
- 依赖：撮合模型契约、账户历史完整性。
- 实现难点：公开 API 可能不披露实际对手方，路由会产生假象。
- 风险或误判来源：做市、再平衡和高频策略可能产生相似统计形态。
- Acceptance criteria：只有明确对手方证据时运行；输出必须是 anomaly signal，
  不作违法结论。
- 建议优先级：低。

## 5. 多地址实体聚类

- 研究价值：探索地址之间可能共享的行为或资金特征。
- 所需新增数据：链上直接边、时间序列、经过验证的共同属性。
- 依赖：资金流覆盖与严格的负样本设计。
- 实现难点：托管、交易所和公共路由导致大量伪关联。
- 风险或误判来源：统计相似不等于共同控制。
- Acceptance criteria：每个簇列出规则、证据、替代解释和人工复核结果。
- 建议优先级：低。

## 6. 事件时间窗与 insider-risk 模型

- 研究价值：比较公开事件前后的建仓与价格变化。
- 所需新增数据：版本化公开事件时间、完整交易历史、价格历史和结算时间。
- 依赖：事件来源白名单、市场—事件映射、时区统一。
- 实现难点：首次公开时间和信息扩散时点难以证明。
- 风险或误判来源：选择偏差、事后挑选窗口及混杂新闻。
- Acceptance criteria：预注册窗口与阈值，输出仅为 exploratory heuristic，并
  提供替代解释。
- 建议优先级：中。

## 7. 策略特征工程及回测

- 研究价值：评估可重复行为模式在历史样本中的稳定性。
- 所需新增数据：完整交易、市场状态、价格、费用和结算数据。
- 依赖：无前视偏差的数据快照与版本化公式。
- 实现难点：幸存者偏差、成交可实现性和费用建模。
- 风险或误判来源：过拟合及把相关性当作因果性。
- Acceptance criteria：时间切分、基准策略、交易成本和可复现实验哈希齐全。
- 建议优先级：中。

## 8. 实时监听与异常告警

- 研究价值：在新交易出现时及时生成待核查信号。
- 所需新增数据：稳定实时流或低延迟官方轮询接口。
- 依赖：历史基线、限流策略、断点续传和告警抑制。
- 实现难点：重复事件、乱序、重试风暴和误报管理。
- 风险或误判来源：短期噪声被误当异常。
- Acceptance criteria：断线恢复无丢失、告警可追溯、误报率有监控。
- 建议优先级：低。

## 9. Dashboard

- 研究价值：集中展示覆盖、指标、证据和人工核查状态。
- 所需新增数据：经过白名单导出的聚合 JSON。
- 依赖：稳定指标 schema、静态报告验收和无障碍组件。
- 实现难点：在不暴露 raw/数据库的前提下保持可审计性。
- 风险或误判来源：视觉简化掩盖覆盖不足或口径差异。
- Acceptance criteria：纯静态、无运行时 API、public 泄露检查和无障碍测试通过。
- 建议优先级：中。

## 10. 自动生成研究报告

- 研究价值：从同一证据快照稳定生成周期性报告。
- 所需新增数据：版本化指标、覆盖报告、公式注册表和文本模板。
- 依赖：可重复 normalized pipeline 与稳定报告 schema。
- 实现难点：自动文字可能夸大不确定性或遗漏失败状态。
- 风险或误判来源：把 unavailable 写成零，或把 anomaly signal 写成结论。
- Acceptance criteria：相同输入生成相同哈希；强制展示来源、覆盖和局限；
  禁止定罪式措辞。
- 建议优先级：中。
